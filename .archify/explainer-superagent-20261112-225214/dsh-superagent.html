dsh-superagent 是什么？

长图

答

结论

DeepSeek 开源的研究原型：一个为单个 GitHub 仓库服务的主动式 coding agent，以插件形态跑在 DeepSeek Harness 里。它把"尽量少占人的注意力"当作第一设计原则，并用代码强制的授权模型决定 agent 何时行动、何时开口。1

  1. 事件统一抽象为 Trigger，经确定性 gate 和 LLM 评估两层筛选后才开工。2
  2. 每个任务携带不可变的授权范围 Mandate，超范围必须重新授权。3
  3. 只在人必须决策或能用上结果时才发消息，其余时间保持安静。4
  4. 每个 Ticket 在独立的 worker session 和目录里执行，干到 PR 为止。

适用于dsh-superagent 0.1.0研究原型依据官方 docs 与 package.json

1

一条消息怎么变成 PR？

图的结构
  • GitHub / 飞书消息 msg
  • Trigger 入库 trigger
  • gate 权限检查 gate
  • LLM 评估 eval
  • 只记录不执行 drop
  • Ticket + Mandate ticket
  • Executor Session worker
  • PR 或回复 pr
  • eval → drop · 忽略
  • eval → ticket · 接受
  • gate → drop · 无权
  • gate → eval · 通过
  • msg → trigger
  • ticket → worker · Assignment
  • trigger → gate
  • worker → pr · 交付

所有事件走同一条流水线：先进 gate 过权限，再过 LLM 评估判断价值，授权后交给独立 worker 执行。2

  1. GitHub / 飞书消息 ↗

    任何来源的事件都转成不可变 Trigger；重复接收只产生一个 Ticket，天然幂等。

  2. gate 权限检查 ↗

    白名单与 Policy 由宿主代码强制，消息正文再狡猾也改不了权限。

  3. LLM 评估 ↗

    判断这件事值不值得开工；规则外的主动工作先只记录"本来想做什么"。

  4. Ticket + Mandate ↗

    接受即签发不可变授权：范围、强度、依据的规则。超范围必须开新 Ticket 或问人。

  5. Executor Session ↗

    每个 Ticket 一个 worker session 和独立目录，shell 超 5 秒自动转后台，不阻塞新消息。

  6. PR 或回复 ↗

    需要决策时一次只问人一个结构化问题，其余时间安静干到交付。

2

核心概念各管什么？

领域模型只有少量概念，每个都有明确的规则；业务需求落成概念的属性，而不是新增概念。2

概念是什么它保证的规则
Source事件流（GitHub、飞书）重启不重放事件；丢弃自己的消息
Trigger幂等单位一条不可变事件被接受两次也只建一个 Ticket
Thread按时间排序的 Trigger 序列同一时间最多一个 Eval 在跑
Eval对一批 Trigger 的判断分两层：确定性 gate + LLM 评估
Mandate不可变接受时签发的授权扩大范围必须新建 Ticket
Ticket一个被授权的工作单元只能由 Eval 创建
Policy可回滚版本化的评估规则与白名单规则变更时运行中的 Eval 作废
3

什么时候开口，什么时候闭嘴？

每条消息、每个面板元素都要证明价值大于它消耗的注意力，否则删掉。4

场景agent 的行为
没被点名且没有规则允许冷启动默认不动；想做的只记录，不执行
收到明确请求确认一次，说清要做什么，然后安静干活
干活过程中不发进度消息
有结果可审、需要决策、做不完发一条短消息，聊天消息不超过 100 词
系统健康时安静即正常面板上不占任何空间
4

工程形态什么样？

形态
DeepSeek Harness bundle（插件），cordis 4 组装
语言与构建
TypeScript，tsdown 打包，vitest 测试
Web 面板
React 18，回答三个问题：需要我吗、健康吗、历史如何
运行要求
Node ^22.19 或 >=24，DSH ^0.2.1-alpha.2
状态存储
本地 stateDir，Store 加文件锁，session 可持久化
prompt 治理
团队可改 prompt 分区并版本化；权限部分代码强制，prompt 改不动
5

它不适合什么？

定位与边界

官方声明是研究原型，不是正式产品，不能直接上生产。 只服务一个 GitHub 仓库；没有定时任务、多模型调度、浏览器操控和 CI 发布链路。 深度绑定 DeepSeek Harness 全家桶，脱离它运行成本高。
